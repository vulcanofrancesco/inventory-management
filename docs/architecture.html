Catalyst Components: Architecture

A factory inventory management demo. A Vue 3 single-page app talks to a FastAPI service over REST. The service loads JSON files into memory at startup and does all filtering in Python. There is no database.

Data flow: changing a filter

User picks a filter FilterBar.vue

Time Period, Location, Category or Order Status is written to a shared ref in useFilters, a singleton every view reads.

View reloads its data views/*.vue

The view calls getCurrentFilters() and passes the result to api.js. Time Period is mapped to month.

Query string is built api.js

Values of "all" are dropped, so only active filters become query params, e.g. /api/orders?warehouse=Tokyo&month=Q2-2025.

FastAPI filters in memory main.py

filter_by_month matches order_date against a month or a quarter; apply_filters matches warehouse, category and status case-insensitively.

Response is validated Pydantic

Lists go through models such as InventoryItem and Order; summary and report endpoints return computed dicts.

UI derives what it shows computed()

Raw data lands in refs (allOrders, inventoryItems); KPIs, charts and tables are computed properties on top.

Gaps worth knowing

Tasks endpoints are missing. The frontend calls /api/tasks on every page load and gets a 404.
Purchase-order endpoints are missing. purchase_orders.json is loaded but never served, so "Create PO" has nothing to post to.
Backlog view isn't routed. views/Backlog.vue exists but has no entry in main.js.
Reports bypasses the API client. It hard-codes http://localhost:8001 instead of going through api.js.
